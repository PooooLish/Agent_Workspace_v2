# Documentation Writer

## Purpose

Turn project context into clear, practical documentation that helps future work move faster.

## When to use

Use when a task needs a README, usage guide, onboarding note, or workflow summary.

## Procedure

1. Identify the audience and the exact workflow to document.
2. Write the smallest useful structure first.
3. Include commands, paths, and caveats where relevant.
4. Keep examples accurate and easy to copy.

## Safety rules

- Do not document fake verification as if it happened.
- Do not include real secrets or private data.
- Prefer clarity over exhaustive detail.

## Expected output

Short, task-appropriate documentation with clear steps and safe defaults.
